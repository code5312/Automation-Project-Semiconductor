## C. 반도체 불량 대응·인수인계 자동화

> **“불량을 찾은 뒤 실제 문제 해결까지 여러 부서가 움직이는데, 이 과정 중 사람이 반복하는 전달과 판단을 줄일 수 없을까?”**
> 

### 어떤 문제인가?

반도체 불량 대응 과정에는 한 부서만 참여하지 않는다.

| 부서 | 주요 역할 |
| --- | --- |
| **YI** | 전체 수율 관리, 불량 분석 총괄, 원인 부서 지정 |
| **P-ENG** | 공정 Recipe와 조건 관리 |
| **M-ENG** | 설비 하드웨어 점검 및 수리 |
| **MI** | 불량 감지·계측 데이터 제공 |
| **MFG** | 생산라인 운용 및 LOT Hold |
| **FA** | 불량의 물리·화학적 원인 분석 |

불량 발생 후에는 여러 부서가 데이터를 넘겨받고,

상황을 파악하고, 담당 부서를 결정하고, 다시 결과를 전달해야 한다.

### 현재 조사한 업무 흐름

**① 불량 감지 및 최초 등록**

MI / YI에서 이상 탐지

→ LOT 번호, 불량 위치, 이미지, 불량률 등 등록

**② 긴급 라인 통제**

MFG → 불량 LOT Hold

P-ENG → 관련 설비 Interlock

**③ 데이터 종합 분석 및 담당 부서 지정**

YI에서 데이터를 분석해

→ 설비 문제라면 M-ENG

→ 공정 조건 문제라면 P-ENG

등으로 이슈 전달

**④ 원인 규명 및 복구**

설비 점검 / Recipe 수정 / FA 정밀 분석

**⑤ 검증 및 정상 가동**

YI 최종 승인

→ Hold 및 Interlock 해제

→ 재발 방지 문서 업데이트

## 이 과정에서 발견한 자동화 포인트

### ① 부서 간 담당 판단

공정 문제인지 설비 문제인지 판단이 늦어지면

부서 간 이슈 전달이 반복될 수 있다.

**자동화 아이디어**

센서 시계열 데이터 + 웨이퍼 맵 + 과거 사례 등을 이용해

**가능성이 높은 원인 영역과 우선 확인 부서를 추천**

---

### ② 수동 인수인계 리포트 작성

불량 발생 후 담당자가

- 센서 그래프
- 불량 이미지
- LOT 정보
- 원인 분석
- 조치 결과

등을 직접 정리해 전달해야 한다.

**자동화 아이디어**

데이터를 자동 수집해

> **불량 개요 → 관련 데이터 → 원인 후보 → 담당 부서 → 조치 결과**
> 

형태의 인수인계 문서를 자동 생성

---

### 프로젝트화한다면

**불량 탐지 자체를 새로 만드는 것보다**

> **불량 발생 → 데이터 정리 → 담당 부서 추천 → 인수인계 자료 생성 → 조치 결과 기록**
> 

이라는 **불량 발생 이후 업무 프로세스 자동화**에 초점을 두는 방향을 검토 중이다.

### 현재 고민

> ⚠️ 실제 반도체 회사의 세부 업무 데이터를 확보하기 어렵다.
> 
> 
> 따라서 실제 FAB 전체를 재현하기보다는
> 
> **대표적인 불량 시나리오와 합성 데이터를 활용해 업무 흐름을 구현하는 방식**을 고려하고 있다.
>
