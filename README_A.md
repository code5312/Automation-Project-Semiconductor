## A. 반도체 공정 데이터 코드 리뷰 자동화

> **“공정 데이터 분석 코드는 돌아가는데, 이 코드가 반도체 공정 관점에서도 제대로 작성된 걸까?”**
> 

### 어떤 문제인가?

반도체 공정에서는 장비 센서 데이터, SPC/FDC 데이터, 수율·결함 데이터 등을 분석하기 위해 Python 기반의 데이터 처리 코드가 사용된다.

이 과정에서 공정 엔지니어나 데이터 담당자가 직접 스크립트를 작성하지만,

- 단위 불일치 및 결측치 처리 오류
- 임계값 하드코딩
- 시계열 정렬 오류

같은 문제가 발생하면 **코드 자체는 실행되더라도 분석 결과가 잘못될 수 있다.**

일반 코드리뷰 AI는 문법이나 코드 품질은 확인할 수 있지만,

우리는 여기에 **반도체 공정 데이터의 도메인 규칙을 추가한 리뷰어**를 만드는 방향을 검토했다.

### 우리가 생각한 자동화 흐름

**공정 데이터 분석 코드 입력**

→ **일반 코드 구조 검사**

→ **반도체 도메인 규칙 검사**

→ **LLM 기반 의미 분석**

→ **위험 코드 및 수정 이유 제시**

→ **수정 후 재검증**

### MVP에서 검사할 수 있는 항목

**① 단위 일관성 검사**

온도·압력·유량 등 같은 물리량을 다루는 변수의 단위가 코드 안에서 일관되는지 확인

**② LOT / Batch 조인 무결성 검사**

DataFrame 병합 과정에서 잘못된 Key 사용이나 예상하지 못한 행 수 변화 탐지

**③ 시계열 정렬 검증**

센서별 샘플링 주기가 다를 때 timestamp 정렬·리샘플링 과정이 존재하는지 확인

### AI는 어디에 필요한가?

정적 규칙만으로 판단하기 어려운 부분을 LLM이 보완한다.

예를 들어 변수명이 달라도 같은 물리량인지 파악하거나,

코드 전체 맥락에서 특정 전처리가 실제로 누락된 것인지 판단한다.

반대로 명확하게 판정할 수 있는 부분은 **정적 규칙 기반 검사**를 사용한다.

### 8주 MVP 범위

| 구분 | 범위 |
| --- | --- |
| 대상 | Python 기반 반도체 공정 데이터 전처리 코드 |
| 검사 | 단위 / 조인 Key / 시계열 정렬 등 3~5종 |
| 데이터 | 공개 또는 합성 반도체 공정 데이터 |
| 구조 | 정적 Rule + LLM 결합 |
| 결과 | 문제 위치 / 이유 / 수정 제안 |
| 평가 | 오류 탐지율, 오탐률, 리뷰 시간 감소 |
